# Rasoi Express — Offer Roulette

**DOOMFORGE 2026 · Marketing Track · Case 3 (customer targeting)**
Difficulty: 4 of 5 · 8 hours · teams of 3

Rasoi Express earns about **₹55 profit on an average order before discounts**.
A blanket 20% coupon raises orders but costs more than it earns. Last quarter a
random 20% of customers received an offer, which gives a rare fair comparison.
For each of 200,000 customers, choose **no coupon, 10% off or 20% off** to earn
the most extra profit after paying for every discount, within an ₹80 lakh
discount budget.

This repository is a **half-built system**, not a blank template. It loads the
public data, trains a propensity model, and produces a schema-valid baseline
submission. The baseline answers the wrong question: it predicts *who will
order*, not *who will order because of the coupon*. Your job is to build the
uplift model, the budget-aware assignment, and the business case.

> All customers, orders and offers are synthetic. No API keys, cloud services
> or paid data are required.

## Quick start

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"

make inspect          # trial arms, opt-out share, budget
make train            # fit the shipped propensity baseline
make submit           # writes the baseline submission (~6 s)
make test             # three tests fail by design; see "Known defects"
make lint
make typecheck
```

The public data is about 46 MB (Parquet). Loading and scoring all 200,000
customers fits comfortably in 8 GB RAM. Docker:

```bash
docker build -t rasoi .
docker run --rm rasoi
```

The shipped baseline selects the 50,000 eligible customers with the highest
20%-arm order probability and offers them 20%. It respects opt-outs and its
claimed discount spend is under the budget, but it loses money: the customers
who are most likely to order are also the ones who would have ordered anyway.

Every customer appears exactly once. Opt-outs cannot be contacted. One offer
per customer. The true expected discount spend, measured on hidden response
curves, must be at or below ₹80 lakh. `make submit` must regenerate the files
from `data/public` in the clean-room container.

## How you are scored (100 points)

This is the Marketing track's rubric, not the Finance track's.

| Part | Points | Mode |
|---|---:|---|
| Hidden-data score: extra profit in the organisers' simulator | 40 | automated |
| Hidden-data score: predicted uplift vs the true incremental orders | 20 | automated |
| Memo for the decision-maker | 20 | rubric + human |
| Code reruns cleanly from `data/public` | 10 | automated |
| Five-minute demo | 10 | human |

The 60 hidden points use normalised anchors (floor, shipped baseline,
reference). Matching the baseline earns 40% of the hidden category. A plan that
violates the budget or contacts an opt-out gets **zero** for the profit term
and is flagged to the judges.

### The judgment call

The 20% coupon is not automatically better than 10%. Predict the **change** in
orders for each arm, price the first-order discount, and buy the offers whose
incremental margin per rupee of discount is highest. Then say in the memo whose
profit you are protecting: Rasoi's margin, the customer's experience, or the
₹80 lakh budget.

## Data

`data/public/` is a snapshot at **31 August 2026**. The randomised trial ran in
**September 2026**; the campaign decision is for **October 2026**.

| File | Rows | What it is |
|---|---:|---|
| `customers.parquet` | 200,000 | Features known before the trial |
| `orders_180d.parquet` | 2,082,718 | 180 days of order history |
| `trial.parquet` | 40,000 | Randomised 1:1:1 control / 10% / 20% with 30-day outcomes |
| `campaign.json` | — | Dates, budget and economics |

See [`docs/DATA_DICTIONARY.md`](docs/DATA_DICTIONARY.md) for columns and the
defect classes. The public data does **not** contain the hidden true response
curves, and it does not contain the trial's counterfactual for non-trial
customers.

## Contribution workflow

```bash
git switch -c feat/issue-01-uplift
# code, tests, docs
make test lint typecheck
```

Open a PR using the template, link the issue, and show a before/after metric:
uplift MAE, true extra profit on a holdout, budget spend, or a failing test now
passing. Do not commit generated `submission/*.csv` or the hidden data. Trivial
PRs that only rename variables or remove a test do not score.
